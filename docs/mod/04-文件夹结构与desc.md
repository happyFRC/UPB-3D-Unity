# 04 · 文件夹结构与 desc.json

这一篇讲清楚一个模组文件夹里都有什么、哪些必须有、哪些可以不要。

## 最小结构

一个能运行的模组，最少只要两个文件：

```
HelloWorld\
├─ HelloWorld.cs     ← 主文件，必须有
└─ desc.json         ← 描述，强烈建议有
```

## 主文件：为什么必须和文件夹同名？

游戏的规则是：

1. 模组文件夹名就是模组的"编号"；
2. 这个文件夹里**必须**有一个同名的 `.cs` 文件（比如文件夹叫 `HelloWorld`，就必须有 `HelloWorld.cs`）；
3. 这个主文件里**必须**有一个实现了 `UPBMod` 的类（通常类名也写成 `HelloWorld`）；
4. 游戏只调用主文件里那个类的 `Startup`。

如果你把主文件命名成别的（比如 `Main.cs`），游戏会在面板里提示"缺少主文件 HelloWorld.cs，已跳过"。

## 可以有很多个代码文件

一个模组可以有多个 `.cs` 文件，甚至可以放在子文件夹里。它们会被**一起编译**，主文件可以调用它们里面的东西。

例如：

```
HelloWorld\
├─ HelloWorld.cs           ← 主文件，入口
├─ PlanetHelper.cs         ← 辅助代码
├─ Data\
│  └─ SomeNumbers.cs       ← 子文件夹里的代码也会编译
├─ desc.json
└─ icon.png
```

注意两点：

- **入口只看主文件**：其他文件里就算也写了 `UPBMod` 实现，也不会被调用；
- 子文件夹里的 `.cs` 会被编译，但主文件必须在**模组根目录**。

## desc.json：面板上显示的信息

`desc.json` 是一个用 JSON 格式写的描述文件。字段如下：

| 字段 | 必填 | 作用 | 例子 |
|---|---|---|---|
| `name` | 否（建议填） | 面板里显示的名字，可以中文 | `"我的星球包"` |
| `author` | 否 | 作者名 | `"小明"` |
| `version` | 否 | 版本号 | `"1.0"` |
| `description` | 否 | 一句话说明 | `"新增两颗行星"` |

不填 `name` 时，面板会用文件夹名当名字。

一个完整的例子：

```json
{
    "name": "我的星球包",
    "author": "小明",
    "version": "1.0",
    "description": "新增两颗行星和一颗恒星。"
}
```

### JSON 的几条硬规矩

- 所有文字必须用**英文双引号** `"` 包起来（中文引号 `“”` 会出错）；
- 每一项之间用**英文逗号** `,` 隔开；
- 最后一项后面**不要**加逗号；
- 文件保存为 **UTF-8**；
- 可以用记事本打开检查，但不要用 Word。

如果 `desc.json` 写坏了，模组本身一般还能加载，只是名字/说明显示不出来，日志里会有一行"desc.json 解析失败"。

## icon.png：模组图标（可选）

在模组文件夹里放一张 `icon.png`，模组管理面板里就会显示它。

- 文件名必须是 `icon.png`（小写）；
- 建议正方形，比如 128×128 或 256×256；
- 不放也能用，面板会显示名字的第一个字。

## 不需要的东西

- **不需要** `.csproj`、`.sln` 这些工程文件——游戏不读它们，它们只是给某些编辑器做代码补全用的；
- **不需要** 打包成 dll，游戏直接在启动时编译 `.cs`；
- **不需要** 改游戏目录里的其他文件。

## 一个完整模组的例子

```
Mods\
└─ MyPlanetPack\
   ├─ MyPlanetPack.cs        ← 主文件（入口）
   ├─ desc.json
   ├─ icon.png               ← 可选
   └─ Resource\
      └─ MyPlanetPack\
         └─ Textures\
            └─ planet.png    ← 自己的贴图（第 07 篇讲）
```
